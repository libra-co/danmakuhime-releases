# 主播工具复审 · 2026-09-06

本轮将点歌、投票、多来源消息、翻译拆成独立的内置 Rust 插件，并重做点歌从请求到实际播放的流程。普通配置与历史数据保留，这些变更随 v0.4.1 发布。

## 发现的问题和修复

| 问题 | 用户影响 | 修复与验证 |
|---|---|---|
| 四种业务共用一个运行循环 | 慢速测试翻译会拖住点歌、投票等操作 | 四个独立插件/命令所有者；用挂起的 HTTP 翻译证明其他操作在 500 ms 内响应 |
| 网页链接被当成音乐播放 | 点歌后只是打开网页，音量、暂停和自动下一首不可靠 | 明确演唱/播放模式；B 站与本地音频实际下载、解码、播放；旧链接回到选源 |
| B 站合集默选第一段 | 观众指定版本与实际播放的曲目不同 | 多分 P 必须选具体曲目；审核队列显示已选版本 |
| 没有真实可播放检查 | 下架、试听或不可解码资源通过审核 | 检查完整独立音轨、大小、解码，绑定曲目与有效期；修改音源重新检查 |
| fMP4 音频解码初始化失败 | 在线 AAC 下载成功后播放器仍失败 | 升级 rodio 0.21.1，传入真实字节长度；B 站真实音频与真实设备测试通过 |
| 活跃投票合并选项 | 选项序号改变，观众可能投到错误选项 | 活跃轮禁止合并，结束后保留票数再合并 |
| 新投票覆盖旧结果 | 无法查看上一轮 | 单独保存最近 30 轮结果，页面可展开查看 |
| 来源样式修改触发重连 | 改颜色、名称也会中断消息 | 只有平台/目标/认证变化才重连，无效配置保留原连接 |
| 翻译配置或结果清理范围不准确 | 修改展示丢译文；混合语言漏翻；取消后状态残留 | 精确取消，展示/额度变更保留译文，未知及混合语言交由服务识别，更新取消状态 |
| OBS 外观草稿随轮询重置 | 未保存的字号等改动被清空 | 根据已保存外观内容变化更新草稿；前端回归验证轮询不覆盖输入 |
| 拆分后的 OBS 汇总收到系统事件后停等 | 房间连接后投票/歌单状态不再送到 OBS | 先接收任意事件再分类；集成测试在房间切换后验证组合状态 |
| 共享配置及旧数据迁移 | 来源与翻译保存可能相互覆盖，旧文件点歌模式错误 | 按字段原子保存，各模块独立房间存储；旧数据仅迁移一次并保留原记录 |

## 验收命令

```sh
pnpm test
pnpm build
cargo test --locked --manifest-path src-tauri/Cargo.toml
cargo test --locked --manifest-path src-tauri/Cargo.toml bilibili_search_and_audio_decode -- --ignored --nocapture
cargo test --locked --manifest-path src-tauri/Cargo.toml real_player_pauses_resumes_and_advances_approved_queue -- --ignored --nocapture
```

本轮常规回归结果：58 项前端测试、122 项 Rust 测试通过，正式前端构建通过。后两个测试需要网络或真实音频输出设备，默认 CI 跳过，已分别显式运行通过。音频设备测试音量为零，验证播放器时间、暂停、完成与自动下一首，不依赖人工听感。

原生验收使用独立数据目录。已确认 B 站具体分 P 在应用内实际播放、暂停后进度固定、继续后恢复、停止成功；OBS SSE 中同时保留音乐与投票的公开状态，未携带文件位置或认证密钥。实际声卡上的两首短 WAV 自动衔接测试通过。

## 仍有明确边界

- 在线音乐来源为 B 站。网易云等平台仍只有旧记录兼容，没有宣称搜索或播放这些平台。
- B 站视频标题/上传者不能保证是用户想要的歌手版本，需要主播审核；平台限流、删除和授权限制会显示错误。
- 音频目前先下载再播放，单首上限 64 MB；长音频首次加载时间会更长。
- 真实外部 DeepL、Azure、Twitch、YouTube 账号未参与本轮验收。功能保留，协议测试不能替代这些账号的现场验证。
- 插件是编译内置、各自运行的业务插件，当前没有第三方插件市场。
